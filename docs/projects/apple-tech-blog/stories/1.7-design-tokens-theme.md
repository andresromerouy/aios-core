# Story 1.7: Tokens de diseño y modo claro/oscuro base

## Status

Draft

## Story

**As a** lector del sitio,
**I want** ver una experiencia visual consistente con paleta cálida + tipografía editorial y poder alternar entre modo claro y oscuro,
**so that** la lectura es cómoda según mis preferencias y la del sistema.

## Acceptance Criteria

1. Sistema de tokens CSS implementado vía Tailwind + CSS variables (`--color-bg`, `--color-fg`, `--color-accent`, etc.) referenciados desde la paleta tentativa de PRD §3.5.
2. Modo oscuro implementado vía `dark:` de Tailwind, alternable mediante un toggle en el header (componente client minimal en este story; el header completo viene en Story 3.1).
3. Toggle respeta `prefers-color-scheme` en primera visita y persiste elección del usuario en cookie (server-side legible, evita FOUC).
4. Tipografías cargadas vía `next/font` (Inter para body + IBM Plex Serif para headlines — placeholders sustituibles cuando branding cierre).
5. Sin FOUC (Flash of Unstyled Content) al cambiar tema, ni al primer load.
6. Tokens documentados en `docs/design-tokens.md` para futuro reuso.
7. Compatible con `next-themes` (recomendado) o implementación nativa server-side con cookie + script no-flash.

## Dev Notes

### Decisión sobre paleta y tipografía

**Estos valores son PLACEHOLDERS** hasta el branding sprint cierre. El sistema está diseñado para que cambiar tokens sea **un solo lugar** (`tokens.css` + `tailwind.config.ts`). Los componentes deben referir solo a los nombres semánticos (`bg`, `fg`, `accent`), nunca a colores RGB hardcodeados.

### Próximos cambios esperados post-branding

- Sustituir fuentes (probable: tipografías compradas o open-source más específicas).
- Refinar paleta (especialmente el verde mate exacto y el dorado).
- Posiblemente agregar tokens secundarios (`--color-success`, `--color-warning`, etc.) cuando aparezcan necesidades.

### Riesgos asociados

- **FOUC en dark mode al SSR:** evitar con `next-themes` + sus scripts inline. Validar en producción tras Story 1.5.
- **Cookie HttpOnly:** `next-themes` por default no usa HttpOnly (necesita ser readable por JS). OK para preferencia visual no-sensible.

### Testing

- Sin tests automatizados.
- Smoke test manual: toggle alterna correctamente, persiste tras refresh, `prefers-color-scheme` se respeta en visita anónima.
