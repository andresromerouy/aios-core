# Story 1.3: Provisionar PostgreSQL en Neon y conectar Payload

## Status

Draft

## Story

**As a** dueño-dev,
**I want** una base de datos PostgreSQL gestionada en Neon conectada a Payload vía el adapter oficial,
**so that** el contenido persiste de forma confiable y puedo branchearla para PRs.

## Acceptance Criteria

1. Cuenta Neon creada, proyecto provisionado en una región cercana al público target (`aws-us-east-2` o `aws-sa-east-1`).
2. Variable `DATABASE_URL` configurada en `.env.local` (dev) — **nunca commiteada**.
3. Payload usa `@payloadcms/db-postgres` apuntando a la DB Neon.
4. Migraciones iniciales de Payload corren correctamente (`pnpm payload migrate` no falla).
5. Usuario admin inicial seedeado vía script o creado al primer acceso a `/admin`.
6. Posible loguearse en `/admin` con email/password (sin 2FA aún — eso es Story 1.6).
7. Se documenta en README el flujo para crear un branch de DB Neon por feature (workflow básico).
8. `.env.example` actualizado con la variable `DATABASE_URL`.

## Dev Notes

### Configuración de Payload Postgres (Architecture §3)

```typescript
// src/payload.config.ts (extracto)
import { postgresAdapter } from '@payloadcms/db-postgres';

export default buildConfig({
  db: postgresAdapter({
    pool: {
      connectionString: process.env.DATABASE_URL || '',
      ssl: { rejectUnauthorized: false }, // Neon requiere SSL
    },
    migrationDir: path.resolve(dirname, '../migrations'),
  }),
  // ...
});
```

### Neon region trade-offs

| Región | Pros | Cons |
|---|---|---|
| `aws-us-east-2` (Ohio) | Balance US + LATAM, free tier completo | Latencia +30ms desde España |
| `aws-sa-east-1` (São Paulo) | Mejor latencia LATAM | Free tier limitado, lejos de España |
| `aws-eu-central-1` (Frankfurt) | Mejor latencia España | Lejos de LATAM |

**Recomendación:** `aws-us-east-2` para MVP. Reevaluar tras tener métricas reales de tráfico por región.

### Riesgos asociados

Ninguno crítico. **Edge cases:**
- Si Neon free tier se agota (storage o compute), el blog cae. Mitigación: monitorear via Neon dashboard, upgrade temprano si crece.
- Connection pooling: Payload por default abre 1 connection por request — con muchos serverless functions de Vercel puede saturar. Neon ofrece pgbouncer automático en URL `-pooler`. **Usar `DATABASE_URL` con `-pooler.<region>.aws.neon.tech`** para connection pooling.
